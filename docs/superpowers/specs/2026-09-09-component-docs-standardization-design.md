# 高频组件文档标准化设计

## 目标

建立可持续复用的组件文档结构，并用 Button、Input、Form、Popup、Upload 五个高频组件验证规则。重点提升开发者判断适用场景、确认跨端边界、查阅 API 和处理无障碍要求的效率。

## 范围

本批次包含：

1. 定义公开组件文档的标准章节和最低内容要求；
2. 按标准补齐 Button、Input、Form、Popup、Upload；
3. 扩展现有文档测试，对这五篇样板文档执行结构检查；
4. 保持所有 Props、Events、Slots、Methods 和主题变量与当前源码一致。

不批量修改其余组件文档，不调整组件 API、示例页面、侧边栏、主题样式或依赖。

## 标准章节

样板文档按下列顺序组织；组件不具备某类 API 时可省略对应三级章节，但不得虚构内容：

1. 标题与一句话简介；
2. `何时使用`；
3. `平台兼容性`；
4. `基础用法`；
5. 组件特有用法和边界；
6. `API`；
7. `Props`；
8. `Events`；
9. `Slots`；
10. `Methods` 或 `Expose`；
11. `主题变量`；
12. `无障碍`；
13. 源码路径。

文档只描述当前实现。平台支持不明确时保留已有、可证实的表述，不扩大兼容范围。

## 五篇样板的侧重点

### Button

保留已完成的“何时使用”、Slots、主题变量和无障碍内容，复核 API 标题层级与源码一致性，作为最小交互组件模板。

### Input

保留输入法组合事件说明，补齐主题变量和插槽表格；无障碍部分明确持久标签、错误提示、禁用与只读差异。

### Form

重点说明 Form 与 FormItem 的职责、校验触发和错误呈现；API 分开记录容器、表单项、公开方法与插槽，避免把多个组件契约混在一张表中。

### Popup

重点说明受控显示、遮罩关闭、层级和页面滚动影响；无障碍部分覆盖关闭方式、焦点返回和非手势替代。Methods 或 Expose 仅在源码实际公开时记录。

### Upload

重点说明文件选择、上传职责边界、失败与重试、大小和类型限制；平台兼容性必须依据当前实现。无障碍部分覆盖可读标签、上传进度、失败反馈与删除确认。

## 内容来源与一致性

每篇文档在修改前读取对应组件的 `types.ts`、组件实现及直接使用的主题令牌。文档中的类型、默认值、事件参数、插槽和公开方法必须能在源码中找到依据。

主题变量只列组件实现直接使用的 CSS 自定义属性。若组件仅消费全局令牌，应明确说明其复用全局主题，而不声明组件专属变量。

## 测试设计

扩展 `tests/component-docs.test.mjs`：

- 对五篇样板统一检查 `何时使用`、`平台兼容性`、`基础用法`、`API`、`主题变量`、`无障碍`和源码路径；
- 检查每篇至少包含 Props 表或明确的无 Props 说明；
- 按组件能力检查 Events、Slots、Methods/Expose；
- 避免约束 Markdown 表格空格或列宽等纯格式细节。

## 验证

- 运行 `pnpm test:component-docs`；
- 运行 `pnpm test:docs-structure`；
- 运行 `pnpm docs:build`；
- 使用 `git diff --check` 检查差异。

本批只修改 Markdown 和结构测试，原则上无需运行应用类型检查；若实现过程中触及 Vue 或 TypeScript 文件，则补跑 `pnpm type-check`。

## 完成标准

五篇高频组件文档采用一致的信息顺序，关键 API 均有源码依据，使用边界与无障碍要求可直接执行；结构测试能阻止这些样板后续退化；文档测试和构建通过。
