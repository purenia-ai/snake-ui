# 实时预览失败恢复设计

## 目标

当组件文档右侧 H5 实时预览加载超时时，为用户提供明确、可操作的恢复路径，避免只能阅读启动命令后手动刷新整个文档页面。

## 范围

本批次实现：

1. 超时状态保留 `pnpm docs:dev:preview` 启动提示；
2. 增加“重新连接”操作，重新加载当前 iframe 并重新开始超时计时；
3. 增加“新窗口打开”链接，直接打开当前预览地址；
4. 为加载中、失败和重试状态补充可访问语义；
5. 扩展现有预览结构测试。

不增加自动轮询、后台健康检查、错误日志面板或新依赖，也不尝试从浏览器自动启动本地服务。

## 交互设计

### 加载状态

首次进入和每次手动重试时显示“正在连接 H5 预览…”。状态区域使用 `role="status"` 与 `aria-live="polite"`，让状态变化可被辅助技术感知。

### 超时状态

现有 8 秒超时保持不变。超时后状态区域展示：

- “预览服务未启动”；
- `pnpm docs:dev:preview` 命令提示；
- 主操作“重新连接”；
- 次操作“新窗口打开”。

“重新连接”是原生按钮，“新窗口打开”是原生链接，以保留键盘与浏览器标准行为。

### 重试行为

组件维护递增的重试序号，并把它加入 iframe 的 `key`。点击“重新连接”时：

1. 清除当前超时定时器；
2. 重置 `loaded` 和 `timedOut`；
3. 增加重试序号，强制 Vue 重建 iframe；
4. 启动新的 8 秒超时计时。

不修改预览 URL，因此生产路径、开发环境 LAN host 适配和页面路由保持不变。iframe 成功触发 `load` 后清除计时器并隐藏状态层。

### 响应式行为

桌面端在手机壳状态层内显示恢复操作。移动端现有“在新窗口打开实时预览”入口保持不变，因为移动端不内嵌 iframe，不存在相同的超时状态。

按钮和链接保证清晰的 hover、active 与 `focus-visible` 状态，触控区域不小于 44px。减少动态效果模式下不新增动画。

## 实现边界

预计修改：

- `docs/.vitepress/theme/PreviewFrame.vue`
- `docs/.vitepress/theme/custom.css`
- `tests/preview-structure.test.mjs`

不修改 H5 示例应用、构建脚本或 VitePress 路由配置。

## 测试与验证

- 结构测试检查重试序号参与 iframe key；
- 检查重试函数重置状态、递增序号并重新启动计时；
- 检查错误状态包含重新连接按钮和新窗口链接；
- 检查状态区域的 `role="status"` 与 `aria-live="polite"`；
- 运行 `pnpm test:preview-structure`；
- 运行 `pnpm type-check`；
- 运行 `pnpm docs:build`；
- 使用 `git diff --check` 检查差异。

## 完成标准

预览加载超时后，用户无需刷新文档页即可手动重载 iframe，也能直接在新窗口检查预览地址；加载状态变化可被辅助技术感知；移动端现有行为不退化；测试、类型检查和文档构建通过。
