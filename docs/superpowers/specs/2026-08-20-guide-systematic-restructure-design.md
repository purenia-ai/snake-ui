# Snake UI 指南系统性重构设计

## 目标

将 `docs/guide` 从按现有功能自然堆叠的文档集合，重构为一条清晰的用户旅程：认识 Snake UI、完成安装、跑通首个组件、理解全局能力、接入 CMS、定制主题、从 uView Pro 迁移，并在遇到问题时能够独立排查。

本次只重构指南正文与指南导航，不改组件 API、运行时代码、演示页面或构建行为。所有技术表述以当前源码、类型声明、包清单和已有验证脚本为准，不照搬第三方文案，也不将未验证能力写成支持项。

## 设计原则

1. 结论先行：每页开头先回答“这是什么、何时需要、读完能完成什么”。
2. 最小闭环优先：先给最少配置跑通，再展开完整能力和业务适配器。
3. 一页一责：安装、运行环境、底座、数据契约、编辑器链路和主题配置各自承担清晰职责。
4. 两种接入方式并列：npm 与 `uni_modules` 都给出完整、可执行的路径，不把其中一种写成附注。
5. 渐进披露：基础组件用户不需要先理解 CMS 服务；CMS 用户再进入适配器、诊断和装修数据章节。
6. 契约优先：示例字段、事件、导出和平台限制均与当前实现一致；不确定内容明确标注边界。
7. 可恢复导航：保留已有公开页面路径，新增页面通过侧栏和文内“下一步”形成连续路径。

## 信息架构

### 开始

- `intro.md`：产品定位、适用场景、不适用场景、核心能力、平台与版本边界、阅读路径。
- `getting-started.md`：运行前提、npm 接入、`uni_modules` 接入、插件注册、全局样式、easycom、首个组件、安装检查和下一步。
- `compatibility.md`：Vue 3 与 uni-app 环境要求、内置能力、业务适配器、平台差异和能力边界。

### 核心概念

- `foundation.md`：插件选项、主题与暗色、国际化、HTTP、全局工具、按需导入和样式入口。
- `component-data.md`：普通 Props 与 `datas` 的区别、CMS 数据结构、事件命名、防御性默认值、接口层校验和数据来源。
- `sanke-editor.md`：编辑器保存、后端存储、C 端还原、组件标识、链接服务、扩展组件、诊断与验收的端到端链路。

### 定制

- `multi-theme.md`：快速改主色、多主题注册、暗色模式、全局注入、CSS/JS 使用、主题 API、持久化、常见问题。
- `theme-generate.md`：工具用途、生成步骤、导出结构、接入应用、导出校验和限制。

### 迁移与排错

- `migrate-from-uview.md`：迁移前盘点、移除旧依赖、组件与工具映射、行为差异、分阶段迁移和验收清单。
- `troubleshooting.md`：组件未识别、样式缺失、主题未生效、`uni.$snake` 不存在、CMS 空白或诊断、平台 API 失败等高频问题。

## 页面写作模板

各页按内容需要复用以下顺序，不强求机械地出现全部章节：

1. 页面摘要与适用读者。
2. 最小可运行示例或核心结论。
3. 分场景的完整配置或数据契约。
4. 平台、版本和业务依赖边界。
5. 可执行的检查或验收清单。
6. 指向前置知识与下一步的交叉链接。

代码示例统一使用当前项目已采用的 Vue 3 与 uni-app 写法。安装示例分别覆盖 npm 包路径和 `uni_modules` 相对路径；涉及 Options API、普通 `setup()` 或 `<script setup>` 的地方，只在其确实影响用法时说明差异。

## 导航设计

VitePress 指南侧栏重排为四组：

1. 开始：介绍、快速开始、运行环境。
2. 核心概念：全局配置与底座、组件数据约定、装修编辑器数据对接。
3. 定制：多主题与暗黑模式、主题生成器。
4. 迁移与排错：从 uView Pro 迁移、常见问题。

首页“开始使用”继续链接到快速开始，保证已有入口不失效；介绍页通过顶部导航和侧栏提供产品层信息。现有指南 URL 不重命名，避免产生外部死链。

## 内容去重与边界

- `getting-started.md` 只承担首次接入闭环，完整插件选项移到 `foundation.md`。
- `compatibility.md` 只解释环境和依赖，不重复安装步骤。
- `foundation.md` 解释通用运行时能力，不展开 CMS 数据结构。
- `component-data.md` 定义通用数据约定，编辑器与后端链路留在 `sanke-editor.md`。
- `multi-theme.md` 解释主题机制，`theme-generate.md` 只解释可视化生成工具。
- 各页的重复排错内容收拢到 `troubleshooting.md`，原页保留一行链接或关键警告。

## 事实核验

重写前后核对以下来源：

- `src/uni_modules/snake-ui/package.json` 的入口、导出和 peer dependencies。
- `src/uni_modules/snake-ui/index.ts`、`index.d.ts` 与 `libs` 的公开 API。
- 插件安装、主题、国际化、HTTP 与 CMS 实现中的真实选项和错误行为。
- `pages.json`、demo 入口与现有测试中的 easycom、样式和平台用法。
- 组件文档与源码中的 `datas`、事件、CMS 标识和服务依赖。

如文档现状与源码冲突，以源码为准，并在重构中修正文档；不顺带修改运行时来迁就旧文案。

## 验证

1. 检查 `docs/guide` 内部相对链接与 VitePress 绝对链接均有目标文件。
2. 运行文档格式检查，修复本次修改引入的格式问题。
3. 运行 `npm run docs:build`，确认导航、Markdown、组件嵌入和本地搜索索引可构建。
4. 使用文本搜索核对旧的重复配置、遗漏的迁移入口和明显过时表述。
5. 审阅 Git diff，确保改动限于设计说明、`docs/guide` 与 `docs/.vitepress/config.mts`。

## 验收标准

- 新用户从侧栏进入后，可在快速开始一页完成任一安装方式并渲染首个组件。
- 基础组件用户不会被要求预先配置 CMS 请求、缓存或业务服务。
- CMS 用户能够从数据约定进入编辑器链路，并找到服务注入、扩展和诊断说明。
- 主题用户能从快速改色逐步进入多主题、暗色模式和生成工具。
- uView Pro 迁移页面在侧栏可见，并明确兼容范围不是完整复刻。
- 常见安装与运行问题有集中、可执行的排查路径。
- 文档构建成功，所有本次新增的站内链接有效。
