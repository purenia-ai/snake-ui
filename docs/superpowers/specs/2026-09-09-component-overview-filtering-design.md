# 组件总览筛选增强设计

## 目标

提升组件总览页的查找效率，让用户可以按分类快速缩小范围，并在刷新、前进后退或分享链接后保留当前搜索条件。

## 范围

本批次实现：

1. 在现有搜索框下方增加分类快捷筛选；
2. 搜索词和分类写入 URL 查询参数；
3. 数量反馈同时反映当前分类与搜索结果；
4. 支持浏览器前进、后退恢复筛选状态；
5. 补充键盘、移动端和无结果状态测试。

不展示版本、“新增”、稳定性或废弃状态，因为当前组件注册表没有完整可靠的元数据；不新增依赖，不修改侧边栏和组件文档正文。

## 交互设计

### 分类筛选

筛选项由 `componentGroups` 自动生成，前置“全部”选项，避免维护第二份分类列表。选择分类后仅展示该组；再次选择“全部”恢复完整列表。

CMS 专用总览继续使用 `scope="cms"`。该页面只展示包含 CMS 组件的分类，并保持与全量总览相同的筛选交互。

分类控件使用原生按钮，当前项通过视觉状态和 `aria-pressed` 同时表达。窄屏允许横向滚动，按钮保持至少 44px 的触控高度。

### 搜索与分类组合

搜索只在当前分类中执行。结果提示遵循以下规则：

- 没有搜索词且选择“全部”：显示当前 scope 下的组件总数；
- 没有搜索词且选择具体分类：显示该分类组件数；
- 有搜索词：显示当前分类范围内的命中数。

清空搜索只清除关键词，不改变分类。无结果状态提供“清空搜索”；若搜索词为空但分类无结果，则提供“查看全部”。

### URL 状态

使用 `q` 保存搜索词，使用 `category` 保存分类标题。默认状态不写参数，避免产生冗余 URL。

首次挂载时读取当前 URL；用户修改搜索或分类后使用 `history.replaceState` 更新查询参数，不产生每次输入一条历史记录。监听 `popstate`，在浏览器前进或后退时恢复界面状态。

保留 URL 中其他查询参数与 hash。无效分类自动回退为“全部”，并在下一次状态同步时清理无效值。服务端渲染阶段不访问 `window`。

## 实现边界

主要修改：

- `docs/.vitepress/components/ComponentOverview.vue`
- `tests/docs-structure.test.mjs`

如现有测试职责更匹配，也可以把 URL 行为断言放入专门的组件总览测试文件，但不引入新的测试框架。

## 可访问性与视觉

- 分类按钮使用可见焦点样式；
- 当前分类具有非颜色语义 `aria-pressed`；
- 移动端点击区域不小于 44px；
- 横向滚动区域不隐藏用户正在聚焦的按钮；
- 数量变化沿用现有 `aria-live="polite"`；
- 减少动态效果模式下不增加新的位移动画。

## 验证

- 测试分类列表来源、组合筛选逻辑、URL 参数和 `popstate` 清理；
- 运行 `pnpm test:docs-structure`；
- 运行 `pnpm type-check`；
- 运行 `pnpm docs:build`；
- 使用 `git diff --check` 检查差异。

## 完成标准

用户能在组件总览和 CMS 组件总览中按分类与关键词组合查找；当前条件可通过 URL 保留和分享；前进后退能恢复界面；默认 URL 无冗余参数；移动端和键盘操作可用；相关测试、类型检查和文档构建通过。
