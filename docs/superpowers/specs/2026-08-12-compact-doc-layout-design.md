# 紧凑文档布局与页面导航恢复设计

## 问题

右侧手机预览当前挂载在 VitePress 的 `aside-top` 插槽中。默认页面结构会在它之后渲染“本页内容”导航。手机预览接近一个视口高，导致页面导航被推到固定右栏的下方，视觉上像是消失。

同时，左侧目录、正文和右侧预览占用宽度偏大，在常见桌面分辨率下内容显得拥挤。

## 方案

保持 VitePress 默认布局，不自行重写导航组件。

将桌面手机预览从 `aside-top` 移到 `aside-outline-after`：右侧先显示 VitePress 原生“本页内容”导航，再显示手机预览。移动端的 `doc-before` 新窗口入口保持不变。

整体宽度调整为紧凑档：

- 左侧栏变量 `--vp-sidebar-width`：桌面设为 `232px`。
- 正文 `content-container` 最大宽度：`620px`。
- 手机框宽度分档：常规桌面 `250px`，1500px 以上 `280px`，1920px 以上 `320px`。
- 右侧栏宽度继续由手机框宽度统一驱动，保证 `.aside`、`.aside-container` 与 `.aside-curtain` 不裁切。

手机框缩减装饰占用：标题间距、外壳内边距、圆角与阴影稍微收紧；iframe 继续 `scrolling="auto"`，保持真机比例，并受视口高度限制。

## 验证

- 结构测试断言桌面预览使用 `aside-outline-after`，不再使用 `aside-top`。
- 结构测试断言紧凑的左栏、正文和手机宽度变量存在。
- 运行预览结构测试、类型检查和 VitePress 构建。
- 浏览器工具可用时检查页面导航位于手机预览上方；若本机浏览器内核仍故障，则明确记录环境限制。
