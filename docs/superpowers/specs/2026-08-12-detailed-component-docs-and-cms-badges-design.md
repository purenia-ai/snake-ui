# Snake UI 详细组件文档与 CMS 标识设计

## 背景

Snake UI 现有 32 篇组件文档已经接通 VitePress 导航和 uni-app H5 实时预览，但详细程度不一致。12 篇基础组件文档偏简略，20 篇商城装修业务组件对 `datas`、`setStyle`、事件和运行依赖的说明也缺少统一结构。与此同时，侧边栏无法直观看出哪些组件属于 CMS 页面装修体系。

本次参考 uView2 组件文档的信息组织方式，但所有接口、示例和兼容性结论均以 Snake UI 当前源码与实际构建结果为准，不照搬 uView2 未实现的能力。

## 目标

- 32 篇组件文档使用统一、详细且便于检索的内容结构。
- 20 个商城装修业务组件在侧边栏和文档标题处同时显示绿色 `CMS` 标识。
- 12 个基础组件不显示 `CMS` 标识。
- 保留现有右侧手机实时预览、路由和布局行为。
- 文档中明确区分已支持能力、预留参数、平台限制和业务适配要求。

## 组件分类

### 基础组件（12 个）

Button、Icon、Image、Lazy Image、Swiper、Tabs、Notice Bar、Loadmore、Empty、Overlay、Popup、Sticky。

这些组件是可独立使用的公开基础能力，不显示 `CMS` 标识。

### CMS 组件（20 个）

Snake CMS、自定义模块、图片展示、轮播广告、魔方布局、视频、富文本、公告、辅助分割线、图文导航、商品搜索、悬浮入口、页面弹窗、小程序跳转、关注、商品列表、活动列表、筛选排序、列表切换、优惠券。

这些组件服务于商城页面装修、配置驱动渲染或 CMS 容器内部组合，统一显示 `CMS` 标识。

## CMS 标识设计

### 侧边栏

VitePress 原生侧边栏项目只接收文本，因此在 CMS 导航文本中加入统一的标识元素或由主题层根据显式元数据渲染。标识视觉为绿色胶囊：短文本 `CMS`、小字号、轻背景、深绿色文字，不影响长标题换行和当前项高亮。

优先使用显式配置而非根据分组名称或 URL 猜测，避免以后新增非 CMS 业务分类时误标。

### 文档标题

CMS Markdown 的一级标题后添加统一的 `<span class="cms-badge">CMS</span>`。标识与标题基线对齐，暗色模式保持可读性，移动端不撑宽内容区域。

标识只表达组件类型，不代表版本、稳定性或付费能力。

## 统一文档模板

每篇组件文档按适用内容使用以下顺序；没有对应能力的章节明确省略，不添加空表格。

1. Frontmatter：保留 `preview`，CMS 组件增加显式分类字段。
2. 标题：中文名、英文组件名，CMS 页面追加标识。
3. 简介：解决什么问题、适用场景和边界。
4. 平台兼容性：H5、微信小程序、App，使用“支持 / 有限制 / 不支持”。
5. 基础用法：可直接复制的最小示例。
6. 进阶用法：根据真实能力提供状态、方向、样式、数据源或组合场景。
7. 数据结构：对象和数组 Props 单独说明字段、类型、是否必填、默认行为。
8. API：Props、Events、Slots、Methods / Expose。
9. 注意事项：平台差异、定位与滚动语义、接口依赖、当前实现限制。
10. 源码位置：使用仓库相对路径。

## CMS 数据说明

CMS 组件通常使用 `datas` 或 `setStyle` 对象。每篇文档需要：

- 给出完整但最小可运行的数据示例。
- 列出字段名称、类型、默认行为和业务含义。
- 标记必填字段及缺失时的表现。
- 说明点击跳转、请求、缓存、页面滚动等外部适配依赖。
- 区分纯展示字段与会触发副作用的字段。

Snake CMS 容器额外保留并扩充组件映射、商品数据流、分页方法和自定义插槽说明。

## 兼容性说明

统一使用下表：

| H5 | 微信小程序 | App |
| :-: | :-: | :-: |
| 支持 | 支持 | 支持 |

如果组件依赖平台专有 API、WebView、微信开放能力、CSS fixed/sticky 或原生媒体能力，对应单元格标记“有限制”，并在表格下解释具体条件。兼容性以现有三端构建和源码条件编译为依据；未经真机验证的能力不宣称“真机验证通过”。

## 实施边界

- 不修改组件公共 API、运行逻辑和 npm 导出。
- 不新增 uView Pro 依赖。
- 不改变 32 个 `preview` 路径、示例路由和手机预览通信方式。
- 不恢复“从 uView Pro 迁移”导航入口。
- 不复制参考项目的源码链接、品牌内容或尚未实现的 Props。

## 验证

- 20 个 CMS 侧边栏条目均显示 `CMS`，12 个基础组件均不显示。
- 20 篇 CMS 文档标题均显示标识，且暗色模式、窄屏布局正常。
- 32 篇文档都包含简介、兼容性、基础用法和 API；对象型配置按需包含数据结构。
- 文档记录的 Props、默认值、事件、插槽和方法与源码一致。
- 32 个 frontmatter 与 32 个 uni-app 示例路由仍一一对应。
- `test:preview-structure`、类型检查、H5/微信小程序/App 构建和 VitePress 构建通过。

## 完成标准

使用者仅阅读单篇文档即可判断组件用途、平台支持、最小接入方式、完整公开接口、配置结构及限制；并可通过侧边栏和页面标题立即辨别 CMS 组件与基础组件。
