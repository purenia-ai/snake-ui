# Snake UI 基础组件完整化设计

## 背景

Snake UI 已经具备组件注册、npm 导出、VitePress 文档和 uni-app 预览框架，但当前基础组件多数仍是轻量封装。与 uView Pro 的成熟组件相比，现有实现缺少完整状态、动画、事件、平台兼容处理和可复用内部能力，无法承担正式公共组件库的基础设施职责。

本次以 uView Pro 的 MIT 许可实现为成熟参考，在 Snake UI 内完成适配和重构。迁移后的实现保持独立发布，不要求使用者安装 uView Pro。

## 目标与兼容边界

- 保留现有 `snake-*` 组件标签、Props、事件、插槽和导出名称，现有调用不因升级失效。
- 补齐与 uView Pro 同等级的核心能力，包括状态、动画、尺寸、主题、事件和跨端行为。
- 全局命名空间统一为 `uni.$snake`，不新增或保留 `uni.$u` 运行时依赖。
- 主题继续使用 Snake UI 品牌色和 CSS/SCSS 变量，不复制 uView Pro 的视觉品牌。
- 支持 H5、微信小程序和 App，组件实现不得以浏览器 DOM 作为唯一运行基础。
- 来源于或实质改造自 uView Pro 的代码继续遵循 MIT 许可，并维护第三方声明。

不兼容 `<u-*>` 标签、`uni.$u` 或 uView Pro 的包路径。这些属于迁移来源而不是 Snake UI 的公共 API。

## 实施方案

采用“成熟源码适配 + Snake API 兼容层”的方式，而不是继续扩展现有简化壳组件。

每个组件以 uView Pro 的平台处理和交互行为为基础，完成以下转换：

1. 将组件名、类名、注入键和运行时访问统一为 Snake UI 命名。
2. 将公共属性映射到 Snake UI 的类型定义，并保留现有同名属性及默认值。
3. 用 Snake UI 的主题变量替换视觉常量。
4. 移除对 uView Pro 插件实例、工具目录和隐式全局对象的依赖。
5. 把多个组件共享的能力下沉到 Snake UI 公共底座，避免逐组件复制。
6. 为迁移差异增加兼容测试和文档，不静默改变旧行为。

## 公共底座

第一阶段先建设下列内部能力，供后续基础组件复用：

- `snake-transition`：进入、离开动画，支持时长、缓动、初始样式和结束事件。
- `snake-loading-icon`：圆环、花朵等加载形态，支持尺寸、颜色、垂直排列和提示文字。
- 父子组件通信：基于 Vue provide/inject 的类型化协议，支持子组件注册、排序和卸载。
- 节点测量：封装 `uni.createSelectorQuery`，统一组件内、页面内和异步渲染后的测量行为。
- 平台适配：集中处理 H5、小程序、App 的事件、样式与生命周期差异。
- 节流防抖：为点击、滚动和触摸交互提供可取消、类型安全的工具。
- 层级管理：集中维护遮罩、弹层、通知等组件的默认 z-index。
- 样式与单位：规范数值、`px`、`rpx`、百分比以及安全区的转换和输出。

底座能力放入普通 `libs` 和公共组件目录；不重新建立 `_internal` 组件目录。仅实现协议可放入 `libs/internal`，且不从 npm 公共入口导出。

## 第一批核心组件

### Button

在保留 `type`、`plain`、`disabled`、`loading` 和 `customStyle` 的基础上，补齐尺寸、形状、镂空、图标、加载状态、点击节流、表单行为和小程序开放能力。事件需正确透传点击及平台原生交互结果。

### Icon

从少量硬编码图标升级为正式图标组件，支持完整图标资源、颜色、尺寸、粗细、标签、布局、旋转和点击事件。图标字体或资源必须随 npm 包发布，并允许自定义图标字体扩展。

### Image 与 LazyImage

补齐加载、失败、占位、圆角、裁剪模式、宽高、淡入、预览和插槽。懒加载需使用跨端可行的可视区域检测，并在不支持的平台安全降级。

### Overlay

补齐动画、透明度、层级、锁定滚动、样式覆盖和点击事件；作为 Popup、Modal 等组件的统一遮罩实现。

### Popup

基于 Overlay 和 Transition 实现上下左右及中间弹出、圆角、尺寸、关闭按钮、安全区、点击遮罩关闭、异步开关和完整生命周期事件。保留现有 `open`、`close` 调用方式，并修复已声明但未触发的事件。

### Sticky

使用节点测量和滚动状态实现跨端吸顶，不仅依赖 CSS `position: sticky`。支持偏移量、容器约束、层级以及 `fixed`、`unfixed`、`change` 事件。

## 后续批次

第二批升级 `Tabs`、`Swiper`、`NoticeBar`、`DropMenu`、`DropMenuItem`、`IndexList`、`IndexAnchor`、`Empty` 和 `Loadmore`。重点补齐触摸交互、联动测量、动画、受控状态和生命周期事件。

第三批新增正式组件库常用能力：Form、Input、Textarea、Cell、Grid、Badge、Tag、Search、Modal、Toast、ActionSheet、Checkbox、Radio、Switch、Slider 和 Upload。

各批次完成后保持相同的注册、导出、文档和测试标准；组件清单不再用目录存在作为“完成”标准，而以公共 API 和跨端行为完整为准。

## API 与废弃策略

- 旧 API 与新能力冲突时，优先保留旧行为，并通过适配层提供新能力。
- 必须删除或改名的 API 先进入废弃周期，开发环境给出一次性警告。
- 废弃信息写入类型注释、组件文档和迁移指南。
- 组件默认值集中定义，SFC、类型声明、文档和测试使用同一事实来源或由测试校验一致性。
- 公共组件和类型从根入口导出；内部协议、测量器和工具不作为稳定 API 承诺。

## 主题与样式

视觉基线接近 uView2 的成熟度和密度，但使用 Snake UI 的颜色、圆角和阴影体系。组件样式满足以下要求：

- 所有关键颜色和尺寸提供主题变量与安全 fallback。
- 禁用、加载、按压、聚焦、错误等状态具有明确视觉反馈。
- H5 鼠标交互与移动端触摸交互都可用。
- 不把页面级样式泄漏到宿主项目，也不依赖文档站样式才能正常显示。
- 示例页与真实 npm 安装场景使用相同组件入口。

## 文档与演示

每个正式组件包含：基础用法、完整 API、事件、插槽、方法、主题变量、平台差异和迁移说明。手机预览展示真实 uni-app 示例，而不是单独编写一套静态 HTML。

组件总览按基础、表单、反馈、展示、导航和 CMS 业务组件分类。CMS 组件继续显示明确标识，避免与无业务依赖的公共基础组件混淆。

## 验证策略

- 单元测试覆盖属性默认值、受控状态、事件、暴露方法和父子通信。
- 组件契约测试校验类型、根导出、easycom、npm 文件清单和文档 API 一致性。
- 交互测试覆盖 Popup 动画与关闭、Sticky 状态、Image 加载失败、Button 节流等关键路径。
- 分别执行 H5、微信小程序和 App 构建，发现平台条件编译和 API 差异。
- 构建 VitePress，并验证手机预览能加载对应路由。
- 每批迁移后运行现有测试，确保 CMS 组件和旧调用未被基础能力升级破坏。

## 交付顺序

1. 建立公共底座及对应测试。
2. 完成第一批七个核心组件及兼容测试。
3. 更新导出、easycom、主题、文档与演示。
4. 完成三端构建和文档构建验证。
5. 再进入第二批交互组件，避免在底座未稳定时大面积并行迁移。

## 非目标

- 不复制 uView Pro 的品牌名称和视觉主题。
- 不提供 `uni.$u` 兼容别名。
- 不要求业务项目修改为 `<u-*>` 标签。
- 第一批不一次性迁移全部八十余个组件。
- 不借本次迁移重写 CMS 业务模型；CMS 组件只接受必要的兼容性修复。
