# Snake UI 组件库分批优化设计

## 目标

参考 uView Pro 成熟的组件能力组织、交互状态和演示结构，系统优化 Snake UI 除 Button 外的组件。优化覆盖组件实现、移动端演示、公开文档和回归测试，同时保持现有 API 兼容及 Snake UI 自有主题风格。

## 核心原则

- 采用分批兼容增强，不一次性混改全部组件。
- 保留现有 Props、Events、Slots、默认值和导出路径；已确认的缺陷修复除外。
- 参考 uView Pro 的能力边界与交互经验，不复制其源码或恢复 uView 运行时依赖。
- 优先使用现有 `--snake-*` 主题变量、基础组件和工具，不引入新依赖。
- 每批独立实现、验证和提交，确保问题能够定位和回退。

## 优化批次

### 第一批：基础与反馈

范围包括 LoadingIcon、Transition、Icon、Image、LazyImage、Empty、Loadmore、NoticeBar、Overlay、Popup、Sticky。

重点检查加载与错误状态、图片回退、动画生命周期、浮层层级、滚动锁定、关闭行为、触摸穿透、固定定位、长文本布局和无障碍提示。

### 第二批：表单

范围包括 Form、FormItem、Input、Textarea、Checkbox、CheckboxGroup、Radio、RadioGroup、Switch、Slider，以及与表单协议直接关联的组件。

重点检查双向绑定、校验触发、禁用与只读、清空、字数限制、组合控件协议、键盘与焦点、触摸范围、事件载荷和表单提交行为。

### 第三批：导航与布局

范围包括 Navbar、Tabs、Swiper、Subsection、ButtonSort、DropMenu、DropMenuItem、IndexList、IndexAnchor 及同类导航布局组件。

重点检查安全区、吸顶、滚动同步、活动态、溢出、动画、下拉定位、索引触摸导航、受控状态和不同屏幕宽度布局。

### 第四批：CMS 与商品业务

范围包括 CMS 内容、CMS 营销、商品列表、筛选排序、活动列表、优惠券及其他业务组件。

重点检查空数据与异常数据容错、图片比例、响应式布局、业务事件、旧数据适配、分页与状态呈现，并避免把具体业务接口耦合进展示组件。

## 单组件优化流程

每个组件按同一顺序检查：

1. 对照当前实现、文档、演示和测试建立现状清单。
2. 对照 uView Pro 对应组件确认值得吸收的能力和交互细节。
3. 修复明确缺陷，并优化尺寸、间距、状态、动效和跨端实现。
4. 将演示页按基础用法、变体、状态和高级能力分组，保留实时配置。
5. 同步更新类型注释、组件文档和 API 表。
6. 增加覆盖关键行为与结构的回归测试。

## 演示与视觉规范

- 演示页延续 Button 优化后的信息结构：实时预览在前，能力分组在后。
- 全宽内容纵向排列，紧凑控件使用支持换行的横向容器。
- 统一分组标题、间距、卡片边界和移动端留白。
- 主题色、文字色、圆角和动效由 Snake UI 变量控制，不直接植入 uView Pro 视觉变量。
- 暗色模式、窄屏、长文本、空数据、禁用和加载状态必须保持可读。

## 兼容与异常处理

- 公开 API 的新增项必须有明确使用场景，并提供默认值、类型注释和文档。
- 行为修复可能改变现有表现时，通过测试记录新契约，并在批次总结中明确说明。
- 查询节点、触摸坐标和平台能力不可用时提供安全回退。
- 异步任务、监听器和计时器在组件卸载时清理。
- 禁用、加载和错误状态不得误触发业务动作。

## 测试与验证

每批至少执行：

- 受影响组件的契约与行为测试。
- 演示结构和文档结构测试。
- TypeScript 类型检查和 ESLint。
- 全量测试。
- H5 构建和 VitePress 文档构建。

涉及浮层、滚动、触摸或小程序差异的组件，还需检查相应平台分支的编译结果；无法在当前环境实际运行的平台会在交付说明中标注。

## 提交策略

- 本设计稿单独提交。
- 后续每一批使用独立功能提交，提交中包含组件、演示、文档和测试。
- 不把构建产物、缓存或无关工作区改动纳入提交。

## 验收标准

- 四批范围内的组件均完成实现、演示、文档和测试检查。
- 现有公开用法无需迁移即可继续工作。
- 主要能力能在演示页直接查看，移动端无明显溢出或拥挤。
- 明确的交互缺陷得到修复，并有回归测试保护。
- 每批类型检查、lint、全量测试、H5 构建和文档构建通过。
